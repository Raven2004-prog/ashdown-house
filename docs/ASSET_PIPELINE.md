# Blender To Godot Asset Pipeline

## Toolchain

- Blender 4.5 LTS portable is the production modeller.
- Godot 4.7.x Forward+ is the runtime and final lighting environment.
- glTF 2.0 binary (`.glb`) is the approved interchange format.
- Blender source remains in `res://assets/source/blender/`.
- Approved exports go to `res://assets/hd2d/` and are committed with their source.

## Coordinates And Scale

- Work in metric units with unit scale `1.0`.
- One Blender unit equals one metre in Godot.
- Apply rotation and scale before export.
- Model around a useful placement pivot: floor centre for furniture, hinge for doors, grip/contact point for handheld props.
- Blender's glTF exporter performs the coordinate conversion; do not manually rotate the exported root.

## Naming

- `M_Name`: visible mesh object.
- `MAT_Name`: material.
- `RIG_Name`: armature.
- `SOCKET_Name`: empty used as an attachment point.
- `M_Name-col`: static triangle collision generated by Godot.
- `M_Name-convcol`: convex collision for simple movable shapes.
- `COL_Name-colonly`: collision-only mesh removed from rendering by Godot.
- `Name-noimp`: helper excluded from the imported scene.
- Animation clips end in `-loop` only when they should repeat.

Names are stable API. Do not rename exported nodes that are referenced by a Godot scene without updating the owner scene and validation data.

## Materials And Textures

- Use Principled BSDF with base color, roughness, normal, emission, and alpha only when needed.
- Keep roughness authored; avoid broad glossy interiors.
- Pack room families into controlled atlases and keep palette variation in material parameters where possible.
- Use nearest filtering with mipmaps after Godot import.
- Keep authored image sources beside the Blender file or under `assets/source/textures`.
- Do not point Blender files at Downloads, temporary folders, or `_staging`.

## Export

Run Blender in the background with the repository export helper:

```powershell
& $blender --background --python tools/art_pipeline/build_pipeline_probe.py -- --project-root $project
```

The helper creates a small source `.blend` and matching `.glb` to verify scale, naming, materials, collision suffixes, and import compatibility. Production builders follow the same conventions.

Export settings:

- glTF binary.
- Selected collection or authored export scene only.
- Apply modifiers.
- Y-up enabled by the exporter.
- Materials and tangents included.
- Cameras and lights excluded unless the asset specifically owns them.
- Animations exported from named actions/NLA tracks.

## Godot Import

- Keep name suffix processing enabled so `-col`, `-convcol`, and `-colonly` work.
- Use Godot-authored lights for gameplay rooms.
- Import animation playback, then set intentionally stepped playback in the character scene/controller.
- Permanent placement, interaction anchors, and puzzle IDs live in authored Godot scenes, not inside opaque Blender geometry.
- Imported models are visual kits. Godot scenes own persistent IDs, gameplay scripts, prompts, and state.

## Validation

Every approved export must pass:

1. Godot imports it without errors.
2. The bounding dimensions match the source metres.
3. Its pivot supports direct placement.
4. Collision exists only where intended.
5. Materials use approved paths and filtering.
6. No temporary camera, light, helper, or duplicated material enters the export.
7. The asset reads clearly at Balanced 3D resolution.
